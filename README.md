# tw-stock-advisor 台股選股顧問

把兩份講義——《從 0 到 1 選出一家好公司》（基本面、金流、籌碼）與《可以用的技術分析》（價量、均線、目標價、停損、盤中意識、大盤判斷）——寫成可執行的規則，提供：

1. **選股推薦**：全市場掃描，基本面健檢合格 ＋ 符合技術面進場型態 ＋ 通過風控，才會推薦
2. **完整操作計畫**：每檔推薦都附進場區、停損價（進場要素消失的位置）、目標價、停利／減碼規則與建議股數
3. **持股紀錄與健檢**：按「我已買進」後開始追蹤，提供損益、距停損、R 倍數、技術面／基本面變化、組合集中度與總風險
4. **即時通知**：盤中每分鐘監控，符合進場、該停損、該減碼、目標達成時推播 LINE（並顯示在網站、瀏覽器通知）
5. **台股大盤**：加權／櫃買即時指數、三大法人、外資期貨與選擇權籌碼、期現貨價差、匯率、強勢族群、成交值排行，綜合判斷「進攻／中性／防守」

> ⚠️ 本系統只是把講義規則程式化，輸出不是投資建議；股票投資有賺有賠，請自行判斷。

## 架構

```
FastAPI + SQLite + APScheduler（Docker 單一容器）
├─ app/data        資料來源：證交所／櫃買每日行情、MIS 盤中即時、FinMind 財報籌碼
├─ app/rules       規則引擎（純函式，有單元測試）
│   ├─ indicators  均線、量比、轉折、格局、箱型、對數角度、位階、波段目標價
│   ├─ technical   6 種進場型態與出場規則
│   ├─ fundamental 財報健檢（獲利、成長、現金流、償債、經營效率）
│   └─ risk        可承受虧損 → 最高進場價、部位大小
├─ app/services    同步、推薦、持股健檢、盤中監控、LINE 通知、大盤
└─ web/            前端（原生 JS + TradingView Lightweight Charts）
```

## 規則對照

### 基本面（《從 0 到 1 選出一家好公司》）

| 講義觀念 | 系統判斷 |
| --- | --- |
| 毛利率長期穩定或上升＝護城河 | 近四季平均毛利率 vs 前四季 |
| ROE 高、ROA 低是警訊（高槓桿） | ROE ≥ 15% 且 ROA < 5% 扣分 |
| EPS 要跟自己比 | 近四季 EPS vs 前四季 |
| 營收成長：YoY 雜訊低、QoQ 穩定成長受資金信賴 | 近三月月營收 YoY、近三季 QoQ |
| 好公司：營業現金流入、投資為負、籌資為負 | 近四季現金流型態（已把累計數還原為單季） |
| 危險：營業沒成長、籌資為正、投資為正 | 直接淘汰 |
| 流動比率 > 200%（排除合約負債）、速動比率避開套牢股 | 流動／速動比率 |
| 應收帳款、存貨是最容易發現盈餘造假的地方 | 應收、存貨年增率遠高於營收年增率扣分 |
| 淘汰沒在賺錢、體質爛的公司；分出龍頭、最賺錢、黑馬 | 近四季虧損淘汰；由虧轉盈標記黑馬 |
| 金流：重疊越多金流主題的個股走越強 | 強勢族群加分 |
| 籌碼：外資投信同買很衝、融資爆增可能是聰明融資 | 法人 5 日買賣超、融資變化 |

### 技術面進場型態（《可以用的技術分析》）

| 型態 | 進場條件 | 停損（進場要素消失） | 停利／減碼 |
| --- | --- | --- | --- |
| 量增突破 | 整理 ≥ 40 天後帶量站上箱頂、量比 ≥ 1.2、站上均線、均線靠攏 | 跌回箱內 | 收破五日線減半、箱型 1:1 目標、跌破月線出場 |
| 季線站回 | 5 日內跌破季線後強勢站回、季線上揚、年線之上（盤中 12:00 後確認） | 回檔關鍵低點 | 再破季線砍 50%、破關鍵價全出、黏在季線不轉強出場 |
| 強勢股回測五日線 | 站上所有均線、多頭排列、角度 ≥ 30°、回測五日線收腳（9:30 後） | 收破五日線 | 12:30 後未站回五日線提前出場、目標滿足壓回出場 |
| 沿月線趨勢股 | 60 日內 85% 沿月線、角度 30~60°、回測月線 | 季線跌破 | 跌破季線出場 |
| 破線反彈短打 | 年線之上、修正後站回五日線、報酬／風險 ≥ 1.5 | 站穩五日線前一天低點 | 收破五日線出場、頸線／季線積極出場 |
| 回檔爆量猜底 | 爆量長黑後第二根延續守低 | 爆量 K 低點 | 未站上五日線離場、目標滿足壓回出場 |

共通過濾：**垃圾時間**（創高壓回後破低）、**量縮緩跌**、**弱位階**、**低過低高不過高**一律綁手；開盤前 5 分鐘不進場；與五日線乖離 > 8% 提醒不要追。

**波段目標價**：起漲點到關鍵壓力的高度，1:1 複製到震盪底之上；健康回檔價＝目標價 −（壓力 − 震盪底）。
**角度**：以對數價格回歸斜率換算，固定「日均 0.5% = 45°」作為基準。
**風控**：資金 100 萬、單筆最大虧損 1 萬、每筆 10 萬 → 進場點與停損點距離不得超過 10%，否則不進場（可在設定頁調整）。

### 交易方式：現股與融資（槓桿）

每筆推薦都同時給出**現股**與**融資**兩種方案，買進時可選擇交易方式：

| | 現股 | 融資 |
| --- | --- | --- |
| 部位大小 | 每筆部位資金與單筆最大虧損取小 | 每筆部位資金視為自備款（上市 6 成、上櫃 5 成可借），但單筆最大虧損不變 |
| 股數 | 可零股 | 必須整張 |
| 成本 | 手續費（折數可設）＋證交稅 0.3% | 另加融資利息（年利率可設，按日計） |
| 監控 | 停損／減碼／停利 | 另監控維持率：< 150% 提醒、接近 130% 追繳線立即推播 |

**何時建議用融資**（延伸規則，講義沒有教，以保守為原則）：設定中有開啟信用帳戶，基本面 A／B，大盤不是「防守」，屬於波段型態（突破、季線站回、回測五日線、沿月線），**追繳價低於停損價**（否則還沒停損就會先被追繳），而且受最大虧損限制後融資確實能買到更多股數。融資成數、利率、維持率都是常見預設值，請在「設定」頁依自己券商的條件修改。

### 大盤判斷

法人選擇權 BC／BP 未平倉變化、正價差擴大＋外資期貨空單增加（開高走低）、外資現貨＋期貨方向、台幣升貶、權值 vs 櫃買、強勢族群。

## 安裝與執行

### 1. 準備金鑰（放在 `.env`，不要提交到 git）

```bash
cp .env.example .env
```

- **FinMind**：到 [finmindtrade.com](https://finmindtrade.com) 免費註冊，把 token 填入 `FINMIND_TOKEN`
- **LINE Messaging API**（LINE Notify 已於 2025/3/31 停止服務）
  1. 到 [LINE Developers](https://developers.line.biz/console/) 建立 Provider → 建立 **Messaging API channel**（會一併建立 LINE 官方帳號）
  2. Messaging API 分頁 → 發行 **Channel access token (long-lived)** → 填入 `LINE_CHANNEL_ACCESS_TOKEN`
  3. Basic settings 分頁最下方的 **Your user ID**（U 開頭）→ 填入 `LINE_USER_ID`
  4. 用手機加這個官方帳號為好友（掃 Messaging API 分頁的 QR code）
  5. 網站「設定」頁按「測試 LINE 推播」
  - 免費方案每月推播則數有限，系統會把同一輪的通知合併成一則送出

### 2. 用 Docker 執行（建議）

```bash
docker compose up -d --build
```

打開 <http://localhost:8000>。資料庫存在 `./data/advisor.db`。Mac 需保持開機才能盤中監控。

### 3. 本機開發

```bash
uv sync
uv run uvicorn app.main:app --reload
uv run pytest
```

## 使用流程

1. 第一次啟動會自動回補歷史資料（「設定」頁可看進度），完成後按「推薦 → 立即掃描全市場」
2. 收到 LINE「符合進場」→ 到「推薦」看計畫 → 實際下單後按 **我已買進**（可修改成交價、股數、停損）
3. 系統開始監控這筆持股：跌破停損、該減碼、目標達成都會推播
4. 實際賣出後在「持股健檢」按 **記錄賣出／減碼**，系統計算已實現損益與勝率

## 歷史回測（純技術面）

```bash
uv run python scripts/backtest.py 75   # 回測最近 75 個交易日的訊號
```

每兩天掃描一次訊號 → 隔日開盤買進 → 依計畫的出場規則逐日出場（最多 30 日），扣手續費 3 折與證交稅。
**未套用基本面與族群金流過濾**（歷史財報需時間點對齊，否則會偷看未來），只用來檢查進出場規則本身。

2026/7/20 ~ 10/21 的結果（653 筆）：整體勝率 30%、平均淨報酬 −0.56%、平均 R 0.16；
「強勢股回測五日線」最好（318 筆，平均 R 0.29、淨報酬 +0.05%），「季線站回」與「破線反彈短打」為負。
樣本只有三個月，不足以下結論，但足以說明：**單靠技術面不夠，講義強調的「兩種武器」缺一不可**。

## 全市場基本面更新

「設定 → 更新全部股票基本面」會依成交金額由大到小更新全部上市櫃普通股（約 2,000 檔）。
本益比、淨值比、殖利率改用證交所／櫃買中心的全市場批次資料，每檔只需 4 次 FinMind 查詢。
FinMind 免費版不能批次查詢，背景工作只用 85% 額度（保留 15% 給網頁即時查詢），所需時間約：

| FinMind | 每小時額度 | 全部更新約需 |
| --- | --- | --- |
| 未設定 token | 300 次 | 約 32 小時 |
| 免費註冊並設定 token | 600 次 | 約 16 小時 |

額度用完會等 15 分鐘再試；重啟伺服器會從中斷處繼續。

## 已知限制

- 日 K 未做除權息還原，除權息當天均線會有落差
- 盤中即時報價使用證交所 MIS 公開介面（約 5 秒更新，非官方 API，可能變動）
- 千張大戶、法人成本線、台版 VIX 需付費資料或其他來源，尚未納入；VIX 請至期交所查看
- 盤中量比使用經驗性的台股成交量分布曲線估計全日量
- 族群分類使用 FinMind 產業別，概念股（CPO、CoWoS…）需自行判斷
