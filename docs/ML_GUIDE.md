# AI 波段進場模型指南（LightGBM ＋ 三欄式標記）

本指南說明網站「AI 模型」的完整流程。程式碼都在專案內、可直接執行，
每個步驟都對應一個檔案，註解為繁體中文。

| 步驟 | 內容 | 檔案 |
|---|---|---|
| 0 | 取得資料：三大法人、融資融券、除權息、加權指數 | `app/data/chipdata.py` |
| 1 | 還原權值價、對數報酬 | `app/ml/features.py` → `adjust_prices`、`price_features` |
| 2 | 籌碼特徵：法人連買天數／參與度、融資券、主力集中度 | `app/ml/features.py` → `chip_features` |
| 3 | 大盤體制濾網 `market_trend` | `app/ml/features.py` → `market_regime` |
| 4 | 講義條件當特徵 | `app/ml/features.py` → `handout_features` |
| 5 | 三欄式標記＋台股交易規則防禦 | `app/ml/labels.py` → `triple_barrier` |
| 6 | Purged walk-forward、LightGBM、early stopping、class_weight | `app/ml/model.py` |
| 7 | 樣本外門檻、上線推薦 | `app/ml/model.py` → `select_threshold`、`app/services/recommender.py` → `apply_ml` |

## 執行方式

```bash
# 1) 回補一年份法人／融資券／除權息／指數（約 30 分鐘，可中斷續抓）
uv run python -c "from app.data import chipdata; print(chipdata.backfill())"

# 2) 訓練（約 1～3 分鐘），印出各折 AUC 與門檻
uv run python -m app.ml.model

# 3) 單元測試（交易規則防禦）
uv run pytest tests/test_ml.py -q
```

網站上：「勝率」頁 →「AI 模型」卡片，有「回補法人／融資券資料」與「重新訓練 AI 模型」按鈕。
每天 21:30 自動增量更新資料，每週六 08:30 自動重新訓練。

## 步驟 0：資料來源（全部免費、每天一次請求）

|---|---|---|
| 三大法人買賣超 | TWSE `rwd/zh/fund/T86` | TPEx `insti/dailyTrade` |
| 融資融券餘額 | TWSE `rwd/zh/marginTrading/MI_MARGN` | TPEx `margin/balance` |
| 除權息 | TWSE `rwd/zh/exRight/TWT49U` | TPEx `bulletin/exDailyQ` |

**主力分點（買超前 10 大分點）**需要 FinMind 付費方案，或證交所有驗證碼的「買賣日報表」，本系統不抓取。
`conc_1/3/5` 特徵程式已寫好，只要把資料匯入 `broker_daily(stock_id, date, top_buy, top_sell)`（單位：張）就會自動啟用。
沒有資料時特徵為 NaN，LightGBM 會自動處理缺值。

## 步驟 1：還原權值價

除息 5 元的股票，除息日開盤「跌」5 元，這不是真的下跌。
`adjust_prices` 把除權息日之前的價格乘上 `參考價 ÷ 除權息前收盤`（向後還原），
所有報酬、ATR、均線都用還原價計算，除權息缺口不會被當成波動或停損。
漲跌停判斷則用**未還原**價格（交易所是以前一日收盤／除權息參考價計算漲跌停）。

## 步驟 2～4：特徵（全部只用 t 日收盤以前的資料）

- **價格與波動**：1／5／10／20／60 日對數報酬、ATR(14) ÷ 股價、布林通道寬度與開口變化、與 5／20／60 日線乖離、量比、距 60 日高點。
- **法人**：外資／投信／自營商的連續買超天數（賣超為負）、當日買超張數 ÷ 成交量、5 日參與度、三大法人 20 日參與度。
- **散戶**：融資／融券餘額變化率、5 日融資變化、券資比、融資餘額 ÷ 均量、資券同增、融資銳減（單日 −3% 且股價下跌，斷頭訊號）。
- **主力集中度**：(前 10 大買超分點 − 前 10 大賣超分點) ÷ 成交量，1／3／5 日（需匯入分點資料）。
- **講義**：28 個是／否條件（站上月線、多頭排列、量縮、創高…）與六種進場型態的「條件符合比例」。
- **大盤體制**：加權指數在 20MA **或** 60MA 之下 → `market_trend = 0`。

> 大盤欄位（指數乖離、報酬）**不給模型學**，只當濾網。原因：同一天所有股票的大盤值都一樣，
> 只有一年資料時，模型會學成「猜大盤」，在不同行情下嚴重失準（實測各折 AUC 從 0.6 掉到 0.4）。

## 步驟 5：三欄式標記（Triple-Barrier）

| 項目 | 設定（`model.PARAMS`） |
|---|---|
| 進場 | 訊號日 t 的**隔日開盤**（t 日收盤才知道訊號，不能用 t 日收盤成交） |
| 上邊界 | 進場價 + 2.0 × ATR(t) → 標記 1 |
| 下邊界 | 進場價 − 1.5 × ATR(t) → 標記 0 |
| 時間邊界 | 10 個交易日，到期以收盤出場，扣成本後 > 0 標記 1 |
| 同一根 K 棒碰到上下邊界 | 保守算停損 |
| 成本 | 0.3855%（手續費 3 折 × 2 ＋ 證交稅） |

**交易規則防禦**（`tests/test_ml.py` 都有測試）：

- 訊號日**收盤鎖漲停** → 排隊買不到，不計入。
- 進場日**一字漲停**（最低價 = 漲停價）→ 買不到，不計入。
- **跳空**越過停損／停利 → 以開盤價成交，而不是理想的邊界價。
- **一字跌停**（最高價 = 跌停價）→ 當天賣不掉，順延到下一個沒鎖跌停的交易日開盤賣出。
- 未來資料不足 horizon 天的訊號不標記（不能用「目前為止」的結果）。

## 步驟 6：防止資料洩漏與過度擬合

1. **Purged walk-forward**：日期切成 5 段測試期，每段只用「更早」的資料訓練，
   並清除訓練期最後 `horizon + 1` 天（這些樣本的標籤結果落在測試期內，會洩漏）。
2. **Early stopping**：用訓練期最後 15% 的日期（同樣 purge）當驗證集，指標用 AUC，耐心 200 棵樹；**不碰測試期**。
3. **不平衡樣本**：`class_weight="balanced"`。
4. **保守的參數**：`num_leaves=15`、`max_depth=5`、`min_child_samples=300`、`reg_lambda=10`、行列抽樣。
5. **選股而不是擇時**：以「當天全市場排名」選股（每天機率前 N%），不受各折模型機率尺度不同影響。

## 步驟 7：什麼時候才建議買進

樣本外預測（模型沒看過的期間）、只看大盤多頭日，切成前後兩半：

- 前半段（選取期）挑排名門檻，後半段（驗證期）確認；
- 兩段都要：每筆期望報酬 ≥ 推薦門檻（預設 +1%）、勝率 ≥ 最低勝率（預設 50%）、
  **且比同期間全體樣本多 0.5 個百分點以上**（證明是模型選股，而不是剛好遇到大漲期）；
- 筆數、股票數量達下限。

都通過才「啟用」。啟用後，個股同時滿足「排名達門檻、大盤多頭、未鎖漲停、基本面合格、其他規則為觀望」
才建議買進，操作計畫與標記完全相同（+2 ATR 停利、−1.5 ATR 停損、10 日到期）。
**沒有通過就只顯示機率與排名，不發推薦**——這是刻意的保守設計。

## 判讀與限制

- AUC 0.5 等於亂猜；日 K 選股模型的樣本外 AUC 能穩定在 0.55 以上就算有用。
- 目前只有約一年資料（含 2026 年 6 月的急跌），各折差異大，結果會隨資料累積改變。
- 大盤體制只用加權指數；上櫃股票也以加權指數判斷。
- 若想調整三欄參數，修改 `app/ml/model.py` 的 `PARAMS` 後重新訓練。
